# Changelog

## 0.4.1

一排恢复三道同时成立的硬门槛。0.4.0 把价格和市值从规则里删掉，和已定口径不一致。

- **一排**：首板或二板，且收盘价严格 < 30 元、个股流通市值严格 < 100 亿、`limit_rate_bp` = 1000。三道都过之后，二板优先于首板，再按封锁强度五键，取前 3。10cm 不足 3 只时名额留空，不用 20cm、30cm 补进一排
- **二排**：仍从没有进入一排的首板、二板里只按五键取前 3。可以含没过价格、市值或 10cm 的股票，也可以含过了三道但没进一排前 3 的 10cm
- **缺字段**：收盘价也列入判定字段。收盘价、流通市值、涨停限幅、封成比、封单额、首次涨停时间有一个为 `null`，或流通市值为 0，进未归类

## 0.4.0

一排、二排不再按收盘价、流通市值和 10cm 硬门槛分档，也不再把不满足门槛的股票定义成二排。

- **封锁强度五键**：封成比 → `seal_to_float_ratio`（封单额 / 流通市值，现算，不覆盖 `seal_ratio`）→ 绝对封单额（仅前两键打平时）→ 首次涨停时间 → `market`、`code`。不设百分比带宽，不做市值分组。流通市值为空或为 0 时，相对市值强度为 `null`
- **一排**：从首板、二板里取最多 3 只。先 10cm，再二板优先于首板，再用五键。10cm 不足 3 只时，名额留给 20cm、30cm
- **二排**：从剩余首板、二板里只按五键再取最多 3 只，可含非 10cm，也可含没进一排的 10cm，不与一排重复
- **缺字段**：龙头仍是缺值排后。一排、二排的判定字段有一个为 `null` 或流通市值为 0，进未归类。`sectors` 为空不影响两排
- **展示**：短格式只报强势板块、三类龙头、一排 3 只、二排 3 只、未归类（没有则写 0，有则最多 3 只）。去掉「共 N 只，取前 3」，不再输出 `row1_total` / `row2_total` / `unclassified_total`

开板次数、最后封板时间、封板时长、封单变化、分歧归类本次不做。价格低于 30 元、流通市值低于 100 亿的观察范围本次删除。

## 0.3.0

**题材归类输入从涨停原因（`limit_up_reasons`）改为板块（`sectors`）**。涨停原因是数据商编辑归因产品、各家口径不一，不参与自动归类；`sectors` 为东方财富行业标签（hybk）原文，由复盘 skill 的 `enrich-events` 自动补齐。归类口径不变：`sectors` 原文归类，不合并近义词、不推断板块层级；`sectors` 为空的股票不参与板块归类和强势板块排序，但仍参与总龙头和一排 / 二排判定。强势板块排序键、一排 / 二排阈值、每类最多 3 只截断均不变。`pick` 输入中 `sectors` 非法（非字符串数组且非 `null`）时报错；`limit_up_reasons` 字段不再读取。

## 0.2.0

一排 / 二排从「全部列出」改为**每类最多 3 只**（`row_display_limit`）：选股是筛选不是抄名单。排序统一为 连板高度（二板优先）→ 首次涨停时间 → 封成比 → 封单额 → `market` → `code`，取前 3；`unclassified_rows` 同样最多 3 只。`pick` 输出新增 `row1_total` / `row2_total` / `unclassified_total`（截断前总数），总数超过 3 时回复注明「共 N 只，取前 3」。输出行序同步改为同一强弱排序（原为 高度 → market → code）。

## 0.1.0

落盘连板选股规则，替换 0.0.1 的占位行为（被问到选股时不再只回答「规则尚未发布」）：

- **题材归类**：按涨停原因（`limit_up_reasons`）原文归类，不合并近义词、不推断板块层级；强势板块按涨停家数 → 板块内最高连板 → 板块内最早涨停时间 → 封单额合计排序，取前 3
- **龙头**：总龙头（全市场最高连板）、板块龙头（强势板块内最高连板）、日内龙头（强势板块内最早涨停）分别列出；并列按首次涨停时间 → 封成比 → 封单额排序
- **一排 / 二排**：一排为首板或二板且收盘价严格 < 30 元、个股流通市值严格 < 100 亿、`limit_rate_bp` = 1000；二排为三项判定字段都有值、但确认不满足一排的首板 / 二板。判定字段为 `null` 的股票不进任何一排，列入 `unclassified_rows`；当天首板和二板都无法判定时，两排留空，`unclassifiable_rows` 按实际缺失字段和只数说明；候选池没有首板或二板时为 `no_row_candidates`
- **输出**：强势板块、龙头、一排 / 二排三张表，每行给命中依据和 `market`、`code`；空值一律按「数据缺失」如实标注
- **空结果**：显式日期先判断交易日，不是交易日直接说明。`get` 之后由 `scripts/cli.py pick` 区分「库内无记录」和「库内无收盘涨停事件」
- **并列**：龙头在首次涨停时间、封成比、封单额之后用 `market`、`code` 决定一只。三个业务键都缺失时，命中依据写明「均缺失；按 market/code 顺序展示」，不写成按缺失字段比较。强势板块不足 3 个则全部列出；四个排序键都相同时按题材原文的 Unicode 码位取前 3。板块内没有任何首次涨停时间时，日内龙头为「数据缺失，无法判定」
- **可执行口径**：`scripts/streakpicker/pick.py`，夹具和测试在 `tests/`

`seal_amount`、`seal_ratio`、`first_limit_time`、`close_price`、`stock_float_market_cap` 只使用 `get` 读到的值。值为 `null` 时按数据缺失处理，不区分数据存放在哪里。本 skill 仍只读复盘 CLI，不写库，不输出买卖指令。

**发布方式**：asharekit 改为整包发布，本 skill 不再单独出 `streak-picker-vX.Y.Z.zip`，随套件版本包 `asharekit-vX.Y.Z.zip` 一起发布。`daily-market-review` 由同级目录定位（`../daily-market-review`），删除 `MARKETREVIEW_SKILL_DIR` 和 `~/.codex`、`~/.cursor` 的查找链；同级目录找不到即报「找不到已安装的 daily-market-review」并停止。skill 文档里的版本号保留为口径记录，发布与安装以套件版本为准。
